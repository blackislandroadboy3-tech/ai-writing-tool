# Streamlit + LLM アプリのセキュリティ診断

アプリ全体を診断し、**セキュリティレポート**を出す。コード・設定は書き換えない（報告のみ）。読んだ人が「何から直すか」を自分で決められるレポートにするのが目的で、修正を頼まれたら、そのとき初めて直す。

## 手順

### 1. 機械スキャン

```
python <このSKILL.mdがあるフォルダ>/scripts/scan.py <診断するプロジェクトのディレクトリ>
```

キー形式の文字列、secrets の git 除外、危険な関数、Streamlit 設定、データファイル、依存関係を一度に洗い出し、「読んで判断が必要な箇所」（キャッシュ、ツール使用、外部 HTTP、アップロード、システムプロンプト）も一覧にする。重要度は暫定なので、次の手順で調整する。

### 2. 利用形態を決める

`references/checklist.md` の「1. 利用形態の判定」を読み、ローカル／社内・LAN／インターネット公開のどれかに決める。同じ「認証がない」でも、ローカルなら問題にならず、公開なら高になる。重要度はこれで大きく変わるので、手がかり（README、デプロイ用ファイル、`server.address`、ユーザーの発言）から判断し、根拠をレポートに書く。判断できなければユーザーに聞く。聞けない状況ならローカルと仮定し、その旨と「公開する場合の追加リスク」を書く。

### 3. コードを読む

`references/checklist.md` の確認項目 A〜I に沿って、主要な `.py` と設定ファイルを読む。特に次の3つの流れを最後まで追う。スキャンは1行ずつしか見られないので、行をまたぐ問題はここでしか見つからない。

- **秘密の流れ**: キーを読み込む行（`os.getenv`、`st.secrets`、入力欄）から、画面・ログ・保存ファイル・キャッシュ・プロンプトのどこに届くか
- **外部テキストの流れ**: アップロード、URL 取得、メール、RAG の結果がプロンプトに入り、その後モデルが何をできるか（表示だけか、ツールでコード実行・保存・外部送信までできるか）
- **共有状態**: `st.cache_resource` / `st.cache_data` / モジュール直下の変数 / 保存ファイルに、利用者ごとのデータが入っていないか

スキャンの指摘は該当行を開いて確かめ、誤検知は外す（付録に理由を残す）。

### 4. 秘密を見ない・書かない

`.env` や `secrets.toml` は開かない。先頭の数文字だけ見る、`head` や `grep` で一部を表示する、といった「少しだけ」も含めて不要。診断に必要な「ファイルがあるか」「キー形式の値がいくつあるか」「git 除外されているか」はスキャンがすでに出しており、値そのものはどの指摘にも使わないから。キーの値がターミナルやレポートに一度でも出ると、それ自体が漏えいになる。別のファイル（履歴など）で見つけた値が本物のキーと同じか確かめたいときは、値を表示せず一致するかどうかだけを返す短いスクリプトで比較する。

コード中やデータファイルで見つけた秘密（キー、パスワード、割引コードなど）をレポートに書くときは、先頭4文字＋伏せ字（`sk-p********`、`Samp*******`）にする。レポートは人に渡されるものなので、秘密を全文で載せるとレポート自体が新しい漏えい元になる。会話履歴などのデータファイルも、件数と項目名の確認にとどめ、本文を引用しない。

### 5. レポートを書く

`references/report-template.md` の構成で、日本語で書く。ID（SEC-001〜）、重要度（高／中／低／情報）、OWASP LLM Top 10 の分類、場所（`file.py:行`）、想定される被害、推奨対策をそろえる。被害は「この利用形態で、誰が何をできて、どう損をするか」を具体的に書く。抽象的な「情報漏えいのおそれ」だけでは、読んだ人が優先度を決められない。

「問題なしと確認した項目」と「未確認の項目」も必ず書く。何を見たのかが伝わり、見ていないものを安全だと誤解させないため。

保存先は、ユーザーの指定があればそこ。なければプロジェクト直下の `SECURITY_REPORT.md` とする。会話には、サマリー（重要度別の件数と、最優先の対応1〜3件）とファイルの場所を短く返し、最後に「修正しますか？」と聞く。

ファイルの書き込みが拒否・制限された場合は、別の手段（シェルのリダイレクトなど）で回避しない。レポート全文を会話で返し、保存できなかったことを伝える。拒否はユーザーや環境の判断なので、それを迂回するのは報告だけを頼まれた診断の範囲を超える。
